# Разработка распределённых программ

Распределённая программа для Rakkan состоит из двух частей:

- **задачи**: модуль WebAssembly, который делает кусок работы
  ([как писать задачи](tasks.md));
- **клиента**: программы на Node.js (или любом языке через
  [HTTP API](http-api.md)), которая режет работу на куски, раздаёт их сети и
  собирает результат.

Этот документ — о клиентской стороне и о том, как спроектировать работу,
чтобы сеть выполнила её быстро и надёжно.

## Как сеть исполняет задачи

```
клиент ── run/map ──▶ локальный узел ──▶ выбор исполнителя ──▶ исполнитель
                       │                   (по загрузке,          │ песочница:
                       │                    capability,           │ модуль + вход
                       │                    лимитам)              ▼
                       ◀───────────── результат (выход, gas, код) ┘
```

1. **Выбор исполнителя.** Узлы каждые несколько секунд рассылают свою
   загрузку: слоты, занятость, capabilities и потолки лимитов. Локальный узел
   выбирает исполнителя, у которого больше всего свободных слотов. При
   равенстве он предпочитает узел, у которого модуль уже есть, затем себя
   (без пересылки), затем узел с меньшей задержкой. Исполнитель должен
   поддерживать все capabilities задачи (`image/1`, `tensor/1`) и допускать
   её лимиты.
2. **Модуль** передаётся исполнителю только при первой задаче, дальше по хешу.
3. **Вход** до 1 МиБ идёт прямо в задаче. Больший вход хранится как блоб, и
   исполнитель скачивает его проверенными чанками с вашего узла и с других
   узлов, у которых этот блоб есть.
4. **Выход** до 1 МиБ возвращается в ответе. Больший выход исполнитель
   сохраняет как блоб, а ваш узел скачивает его к себе до того, как вернуть
   результат. Поэтому результат переживает исполнителя.
5. **Сбой исполнителя** (процесс упал, связь пропала, узел выключили) — не
   ошибка задачи. Узел повторяет задачу на другом исполнителе, до трёх
   исполнителей. Занятый исполнитель не считается сбоем: узел ждёт
   освобождения.
6. **Ошибки самой задачи** (`out_of_gas`, `trap`, …) детерминированы, поэтому
   не повторяются: другой узел упал бы так же.

`map` делает то же для каждого входа и держит в работе столько задач, сколько
свободных слотов во всей сети (`concurrency` меняет это число).

## Проектирование

### Задачи — чистые функции

Задача видит только свой вход и прикреплённые блобы, и результат зависит
только от них. Отсюда три свойства, на которых строится всё остальное:

- **Повтор безопасен.** Задачу можно запустить ещё раз где угодно и
  когда угодно, получится то же. Так сеть переживает сбои, и вам не нужно
  думать об идемпотентности.
- **Результат проверяем.** Другой узел обязан получить те же байты и тот же
  gas. На этом стоят реплики и проверка гостей.
- **Порядок не важен.** Задачи одного `map` независимы и приходят в любом
  порядке, поэтому собирайте результаты по `index`.

Если задаче нужна случайность, передайте зерно во входе (см.
[пример с π](#mapreduce)). Если нужно состояние между этапами, передавайте
его через вход или блобы следующего этапа.

### Размер задачи

Слишком мелкие задачи тратят время на накладные расходы, слишком крупные не
влезают в лимиты и плохо балансируются.

- **Верхняя граница — лимиты.** Одна задача получает до 5·10⁹ gas (около
  0,75 с счёта), 10 с и 64 МиБ памяти (потолок узлов по умолчанию, см.
  [tasks.md](tasks.md#gas-и-лимиты)). Цельтесь в половину бюджета gas, чтобы
  был запас.
- **Нижняя граница — накладные расходы.** Планирование, передача входа и
  ответа и запуск песочницы занимают миллисекунды внутри LAN и больше через
  интернет (несколько сетевых задержек). Задача на 50–500 мс счёта окупает
  их с запасом.
- **Сколько задач.** Хотя бы в 3–5 раз больше, чем слотов в сети
  (`status()`: сумма `slots`). Тогда быстрые узлы возьмут больше задач, а
  медленный узел не задержит конец.

Как измерить: запустите одну задачу локально (`rakkan-node run`) и посмотрите
`gas`. Например, задача Монте-Карло тратит 50 gas на точку, значит
10⁷ точек — это 5·10⁸ gas, примерно десятая часть бюджета.

### Данные: вход или блоб

| Данные | Как передавать |
|---|---|
| маленькие параметры задачи (диапазон, зерно, номер) | `input` |
| свои для каждой задачи и большие (фото, файл) | `putBlob`, затем `inputBlobs` в `map` |
| общие для всех задач (словарь, веса, большой файл) | `putBlob` один раз, затем `blobs: [id]` у каждой задачи |
| выход одного этапа — вход другого | `outputAsBlob: true`, затем `inputBlobs` |

Прикреплённые блобы задача читает кусками (`blob_read`), и исполнитель
скачивает только прочитанные чанки по 1 МиБ. Поэтому тысяча задач над
разными частями файла в 10 ГБ не скачивает файл тысячу раз.

## Шаблоны

### map/reduce

Независимые задачи (map), результаты которых складываются на клиенте
(reduce). Пример — оценка π методом Монте-Карло (`sdk/js/examples/pi.js` и
`sdk/as/examples/montecarlo.ts`).

Задача: точки из генератора, зерно которого во входе.

```ts
import { input, output, readU32, readU64 } from "@rakkan/as/assembly";

export function run(): i32 {
  const args = input();
  if (args.length < 12) return 1;
  let s = readU64(args, 0) | 1;   // зерно xorshift64*, не ноль
  const n = readU32(args, 8);     // сколько точек
  let hits: u64 = 0;
  for (let i: u32 = 0; i < n; i++) {
    s ^= s >> 12; s ^= s << 25; s ^= s >> 27;
    const r = s * 0x2545F4914F6CDD1D;
    const x = r >> 33, y = (r >> 2) & 0x7fffffff;   // две 31-битные координаты
    if (x * x + y * y < (<u64>1 << 62)) hits++;
  }
  const out = new Uint8Array(8);
  store<u64>(out.dataStart, hits);
  output(out);
  return 0;
}
```

Клиент: разные зёрна, `map`, сумма.

```js
const inputs = [];
for (let i = 0; i < tasks; i++) {
  const b = Buffer.alloc(12);
  b.writeBigUInt64LE((BigInt(i + 1) * 0x9e3779b97f4a7c15n) & 0xffffffffffffffffn, 0);
  b.writeUInt32LE(perTask, 8);
  inputs.push(b);
}
let hits = 0n;
for await (const item of mesh.map({ module, inputs })) {
  if (item.error) throw item.error;
  hits += item.output.readBigUInt64LE(0);
}
console.log('π ≈', (4 * Number(hits)) / (tasks * perTask));
```

На кластере из трёх узлов по два воркера:

```
$ node examples/pi.js 48 20000000
π ≈ 3.141568 (error 2.5e-5) from 960000000 points in 0.89s
  oNrC9Hha: 26 tasks
  gbapNMNz: 11 tasks
  wTWs5RP8: 11 tasks
```

Узел, к которому подключён клиент, взял больше задач: у него нет пересылки.

Если reduce тяжёлый (например, слияние больших отсортированных кусков),
сделайте его тоже задачами: второй `map` над группами результатов первого.

### Поиск с ранней остановкой

Нужен один ответ, например прообраз хеша или решение головоломки:
пространство режется на диапазоны, и первая находка останавливает всё
остальное (`sdk/js/examples/search.js`).

Задача возвращает код выхода 0, если нашла, и 1, если нет. Клиент:

```js
for await (const item of mesh.map({ module, inputs, stopOnExitCode: 0 })) {
  if (item.error) throw item.error;
  if (item.exitCode === 0) console.log('найдено:', item.output.readUInt32LE(0));
}
```

Как только приходит задача с кодом `stopOnExitCode`, узел отменяет
выполняющиеся задачи и не запускает остальные; цикл заканчивается. Порядок
диапазонов не гарантирован: если важна первая находка в порядке
пространства, а не любая, соберите все находки и выберите минимальную.

### Большой файл по диапазонам

Файл загружается один раз, прикрепляется ко всем задачам, и каждая задача
читает свой диапазон (`sdk/js/examples/wordcount.js` с
`sdk/as/examples/wordcount.ts`).

```js
const { id } = await mesh.putBlob({ path: file });   // потоком, без чтения в память
const step = Math.ceil(size / parts);
const inputs = [];
for (let off = 0; off < size; off += step) {
  const b = Buffer.alloc(16 + Buffer.byteLength(word));
  b.writeBigUInt64LE(BigInt(off), 0);
  b.writeBigUInt64LE(BigInt(step), 8);
  b.write(word, 16);
  inputs.push(b);
}
let total = 0;
for await (const item of mesh.map({ module, inputs, blobs: [id] })) {
  if (item.error) throw item.error;
  total += item.output.readUInt32LE(0);
}
```

**Границы диапазонов** — главная тонкость: слово, строка или запись могут
попасть на стык. Правило из примера: задача считает вхождение, если оно
*начинается* внутри её диапазона, и для этого дочитывает несколько байт за
его конец. Тогда каждое вхождение посчитано ровно одной задачей. Для
построчных данных то же правило звучит так: строка принадлежит диапазону, в
котором она начинается.

### Много файлов

Каждый файл — свой блоб, и map идёт прямо по блобам
(`sdk/js/examples/thumbnails.js`):

```js
const blobs = [];
for (const f of files) blobs.push((await mesh.putBlob({ path: f })).id);
for await (const item of mesh.map({ module, inputBlobs: blobs, limits: { memoryMB: 64 } })) {
  if (item.error) console.error(files[item.index], item.error.kind);
  else if (item.exitCode !== 0) console.error(files[item.index], 'не изображение');
  else writeFileSync(`thumb-${item.index}.jpg`, item.output);
}
```

Задача с kernels изображений идёт только на узлы с capability `image/1`.
Ненулевой код выхода здесь означает «файл не подошёл» и не мешает остальным.

### Общие данные: прикреплённые блобы

Веса модели, словарь или справочник нужны всем задачам. Загрузите их один
раз и прикрепите (`sdk/js/examples/inference.js` с `sdk/as/examples/mlp.ts`):

```js
const { id } = await mesh.putBlob(new Uint8Array(weights.buffer));
for await (const item of mesh.map({ module, inputs: batches, blobs: [id] })) { … }
```

В задаче tensor kernels берут веса прямо из блоба, минуя память задачи:

```ts
const w1 = Tensor.fromBlob(0, 0, DType.F32, hidden, nIn);
```

Так задача с весами в сотни мегабайт укладывается в 64 МиБ памяти.

### Конвейер из нескольких этапов

Выход одного этапа становится входом следующего и не проходит через
клиента: `outputAsBlob` оставляет большие выходы (больше 1 МиБ) блобами на
вашем узле, а следующий `map` берёт их как `inputBlobs`.

```js
// Этап 1: например, декодировать и нормализовать.
const ids = [];
for await (const it of mesh.map({ module: stage1, inputs, outputAsBlob: true, limits: { maxOutputBytes: 8 << 20 } })) {
  if (it.error) throw it.error;
  ids[it.index] = it.outputBlob;   // ID блоба; it.output пустой
}
// Этап 2: обработать результаты этапа 1.
for await (const it of mesh.map({ module: stage2, inputBlobs: ids })) { … }
```

Выход меньше 1 МиБ приходит в `output` и при `outputAsBlob`. Если хотите
единообразия, загрузите его сами через `putBlob(it.output)`. Одинаковые
выходы дают одинаковый ID блоба, что удобно для дедупликации.

### Итеративные алгоритмы

k-means, PageRank, градиентный спуск: каждая итерация — это `map`, а
состояние (центроиды, ранги, веса) идёт следующей итерации во входе или
блобе.

```js
let centroids = init();
for (let iter = 0; iter < 20; iter++) {
  const { id } = await mesh.putBlob(encode(centroids));   // состояние итерации
  const partial = [];
  for await (const it of mesh.map({ module, inputs: shards, blobs: [dataId, id] })) {
    if (it.error) throw it.error;
    partial.push(decode(it.output));                      // суммы по кластерам на шарде
  }
  centroids = merge(partial);
}
```

Данные (`dataId`) загружены один раз. Исполнители держат скачанные чанки в
своём хранилище, пока хватает места, поэтому следующие итерации на тех же
узлах их не перекачивают.

### Проверка результатов

Узлы сети с сертификатами доверенные, но ошибиться может и честный узел
(сбой памяти), а в открытой сети встречаются чужие. Детерминизм делает
проверку точной: правильный результат у всех одинаковый байт в байт.

- **Реплики** для важных результатов:

```js
const res = await mesh.run({ module, input, replicas: 3 });
// принят ответ большинства; res.replicas показывает, кто расходился
```

  Реплики стоят во столько же раз больше вычислений. При расхождении без
  большинства вызов отклоняется с `no_consensus`.
- **Выборочная проверка** для больших `map`: перезапустите случайную долю
  задач с `replicas: 2` и сравните с первым результатом. Расхождение — повод
  перепроверить всё, что считал этот узел (`item.node`).
- **В открытой сети** результаты гостей проверяются автоматически (см.
  [ниже](#открытая-сеть)).

## Ошибки и надёжность

Элемент `map` — либо результат, либо ошибка; одна неудачная задача не
останавливает остальные. Разделяйте три вида исходов:

| Исход | Пример | Что делать |
|---|---|---|
| ненулевой `exitCode` | «не найдено», «плохой вход» | ваша логика; это результат, а не ошибка |
| ошибка задачи | `out_of_gas`, `trap`, `output_limit` | детерминирована: исправить задачу, поднять лимит или уменьшить кусок; повтор не поможет |
| ошибка сети | `no_capacity`, `worker_crashed` после повторов, `unavailable` | повторить позже; задача чистая, повтор безопасен |

**Сохранение прогресса долгих вычислений.** Записывайте результаты по
`index` по мере прихода (в файл или БД). После перезапуска клиента
запустите `map` только по входам без результата: благодаря чистоте задач
это эквивалентно непрерывной работе.

```js
const done = loadDone();                       // Map index → результат
const todo = inputs.map((x, i) => i).filter((i) => !done.has(i));
for await (const it of mesh.map({ module, inputs: todo.map((i) => inputs[i]) })) {
  if (!it.error) saveDone(todo[it.index], it.output);
}
```

**Таймауты.** `limits.timeoutMs` ограничивает одну задачу на исполнителе, а
`signal: AbortSignal.timeout(…)` — всё ожидание клиента. Отмена закрывает
соединение, и узел отменяет задачи на исполнителях.

**Что переживает сеть сама:**
- падение или выключение исполнителя посреди задачи: повтор на другом;
- потерю связи: узлы переподключаются;
- перезапуск вашего узла: SDK заново загрузит модуль. Сам `map`, шедший в
  момент перезапуска, прервётся; повторите его для оставшихся входов.

## Производительность

- **Не мельчите.** Сотни задач по несколько миллисекунд упрутся в накладные
  расходы. Объединяйте мелкие входы в пачки: одна задача обрабатывает 100
  записей и возвращает 100 результатов.
- **Модуль загружается один раз.** Переиспользуйте один объект `Mesh`: он
  помнит, какие модули уже на узле. Исполнители тоже кешируют модули.
- **Большие данные — блобами.** Не кладите мегабайты в `input` каждой задачи.
  Общие данные прикрепляйте через `blobs`, свои — через `inputBlobs`.
- **Нативные kernels.** Для изображений и матриц используйте
  `rakkan_image_v1` и `rakkan_tensor_v1`: они быстрее чистого WebAssembly
  примерно в 8 раз на умножении матриц, а результат так же детерминирован.
- **Память.** Задаче доступно 64 МиБ. Читайте большие данные кусками
  (`blobs.readInto`), а не целиком.
- **`concurrency`.** По умолчанию `map` занимает все свободные слоты сети.
  Уменьшайте, если сеть общая и не хотите занимать её целиком.
- **Сколько у вас мощности:**

```js
const st = await mesh.status();
const slots = st.load.slots + st.members.filter((m) => m.connected).reduce((n, m) => n + (m.load?.slots ?? 0), 0);
```

## Открытая сеть

Если хозяин открыл сеть для гостей (`status().open`), в ней есть узлы без
сертификата. Это меняет три вещи.

- **Результаты гостей проверяются.** Если задачу считал гость, ваш узел
  перезапускает её на независимом узле (по возможности на участнике с
  сертификатом) и сравнивает результаты. У нового гостя проверяется каждый
  результат, у гостя с хорошей репутацией — не меньше 10%. В результате это
  видно по `checked: true` и списку `replicas`. Обманщик отключается и
  больше не получает работы. Для самых важных вычислений всё равно
  используйте `replicas`: выборочная проверка может пропустить одиночную
  ложь.
- **Гость платит кредитом.** Если ваш клиент подключён к узлу-гостю, другие
  узлы считают для него в пределах кредита. Кредит зарабатывается, когда ваш
  узел считает для других: держите `-workers` больше нуля. Когда кредит
  кончился, задачи отклоняются с `no_capacity` и `not enough credit` в
  тексте.
- **Репутация.** `mesh.trust()` показывает, кто сколько для кого посчитал и
  кого ловили на обмане.

## Языковые модели

Языковые модели считаются не задачами WebAssembly, а встроенным сервисом
узлов. Модель режется по слоям между узлами с флагом `-llm`. Мощные узлы и
узлы с GPU получают больше слоёв, а результат одинаков при любой раскладке.

```js
const { model } = await mesh.importModel({ hf: 'models/Qwen2.5-0.5B-Instruct', quant: 'q8_0' });
for await (const e of mesh.generate({ model, prompt: 'Столица Франции?', chat: true, maxTokens: 50 })) {
  if (!e.done) process.stdout.write(e.text);
}
```

Подробности — в [SDK](sdk.md#языковые-модели) и [HTTP API](http-api.md#языковые-модели).

Для своей нейросети, которая не является языковой моделью, используйте
задачи с tensor kernels (шаблон [общих данных](#общие-данные-прикреплённые-блобы)).

## Тестирование

1. **Задача отдельно:** `rakkan-node run` на типичных и граничных входах
   (пустой вход, максимальный размер, вход на стыке диапазонов). Сравните с
   эталонной реализацией на JS или Python.
2. **Детерминизм:** запустите одну и ту же задачу дважды и сравните выход и
   `gas`; в сети это сделает `replicas: 2`.
3. **Клиент на локальном кластере.** Тестам SDK нужен кластер из настоящих
   демонов, и его помощник `sdk/js/test/cluster.js` подходит и для ваших
   тестов:

```js
import { startCluster } from '/путь/к/rakkan-mesh/sdk/js/test/cluster.js';
import { connect } from '@rakkan/sdk';

const cluster = await startCluster({ nodes: 3, workers: 2 });  // собирает rakkan-node (нужен Go) или берёт RAKKAN_BIN
try {
  const mesh = connect({ socket: cluster.sockets[0] });
  // ... ваша программа ...
  cluster.kill(1);   // SIGKILL узла: проверить, что программа переживает сбой
} finally {
  cluster.stop();    // останавливает демоны и удаляет каталог кластера
}
```

   `startCluster` поднимает отдельную закрытую сеть во временном каталоге;
   `guests: n` добавляет гостей и открывает сеть.

## Чек-лист

- [ ] Задача — чистая функция входа и блобов; случайность из зерна во входе.
- [ ] Задача укладывается в половину бюджета gas и в 64 МиБ на самом большом
      куске (проверено `rakkan-node run`).
- [ ] Задач в 3–5 раз больше, чем слотов в сети; каждая на 50–500 мс счёта.
- [ ] Общие данные — прикреплённые блобы; большие входы — `inputBlobs`.
- [ ] Границы диапазонов обработаны: каждый элемент принадлежит ровно одной
      задаче.
- [ ] Результаты собираются по `index`, не по порядку прихода.
- [ ] Ненулевой `exitCode`, ошибки задачи и ошибки сети обрабатываются
      по-разному.
- [ ] Для долгих вычислений прогресс сохраняется, перезапуск продолжает с
      места остановки.
- [ ] Важные результаты проверяются репликами или выборочно.
