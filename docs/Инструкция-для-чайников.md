# Rakkan Mesh: инструкция для чайников

Здесь пошагово описано, что делать. Есть три роли, выберите свою:

- [**Админ**](#админ-хозяин-сети) создаёт сеть и решает, кого пускать.
- [**Узел**](#узел-участник-с-пропуском) — участник с пропуском: даёт сети свой
  компьютер и пользуется чужими.
- [**Гость**](#гость-без-пропуска) приходит без пропуска, когда сеть открыта.

Как сеть устроена внутри, простыми словами рассказывает
[README-для-чайников.md](README-для-чайников.md).

## Сначала: где взять программу

Всем ролям нужна одна программа — `rakkan-node`. Соберите её из исходников
(нужен [Go](https://go.dev/dl/)):

```sh
git clone <адрес репозитория> rakkan-mesh
cd rakkan-mesh
CGO_ENABLED=0 go build ./cmd/rakkan-node
```

Получится файл `rakkan-node`. Его можно просто скопировать на другие
компьютеры той же системы, больше ничего ставить не нужно.

> Узел лучше всего работает на Linux: там песочница для чужих задач самая
> строгая. На других системах запускайте узел с флагом `-isolation process`.

## Админ (хозяин сети)

Вы создаёте сеть и раздаёте пропуска. Ваш главный инструмент — **корневой
ключ**: им подписываются все пропуска.

### 1. Создать сеть

```sh
./rakkan-node network init -out root.key
```

Команда напечатает **ID сети**, длинную строку вида `12D3KooW...`. Это имя
вашей сети. Передайте его всем, кто будет подключаться: секрета в нём нет.

> ⚠️ **Файл `root.key` — главная тайна.** У кого этот файл, тот хозяин сети.
> Сделайте резервную копию и держите ключ на компьютере, который не нужен для
> работы узлом. В идеале это флешка в ящике стола.

### 2. Выдать пропуск узлу

Человек, который хочет подключиться, присылает вам **ID своего узла** (как
его узнать, см. [раздел про узел](#1-узнать-свой-id)). Вы делаете ему пропуск:

```sh
./rakkan-node network issue -peer 12D3KooW...ID-узла... -out vasya.cert
```

Отдайте файл `vasya.cert` владельцу узла. Пропуск тоже не секрет: он
работает только вместе с ключом того самого узла.

Полезные флаги:
- `-days 30` — пропуск на 30 дней (по умолчанию на год).
- `-roles member,admin` — сделать человека помощником, который сам может
  выдавать пропуска (см. ниже).

Команда печатает **серийный номер** пропуска. Запишите его на случай, если
пропуск придётся отозвать.

### 3. Назначить помощника (необязательно)

Чтобы не доставать корневой ключ каждый раз, можно выдать кому-то пропуск
с ролью `admin`:

```sh
./rakkan-node network issue -peer 12D3KooW...ID-помощника... -roles member,admin -out helper.cert
```

Теперь помощник может выдавать пропуска своим ключом:

```sh
./rakkan-node network issue -key node.key -issuer-cert helper.cert \
    -network <ID сети> -peer 12D3KooW...ID-нового-узла... -out new.cert
```

Ограничения: помощник не может назначать других помощников, а выданный им
пропуск не может действовать дольше пропуска самого помощника.

### 4. Выгнать кого-то

```sh
./rakkan-node network revoke -crl crl.json <серийный номер или ID узла>
```

Команда создаст (или дополнит) файл `crl.json` — **чёрный список**,
подписанный корневым ключом. Список надо раздать сети. Скопируйте файл на
любой работающий узел, запущенный с флагом `-crl crl.json`: узел заметит
обновление за несколько секунд и разошлёт список всем. Подделать список
нельзя, поэтому копировать его можно куда угодно.

### 5. Открыть сеть для гостей (необязательно)

```sh
./rakkan-node network open -pow 24 -policy policy.json
```

`-pow` — сколько гость должен «потрудиться» у входа. 24 — это несколько секунд
работы процессора, каждая единица сверху удваивает время. Файл `policy.json`
раздаётся так же, как чёрный список: положите его на любой узел, запущенный с
`-policy policy.json`.

Закрыть сеть обратно:

```sh
./rakkan-node network close -policy policy.json
```

Гостей отключат, участников с пропусками это не затронет.

### 6. Посмотреть, что внутри файла

```sh
./rakkan-node network show vasya.cert     # пропуск
./rakkan-node network show crl.json       # чёрный список
./rakkan-node network show policy.json    # открыта ли сеть
```

## Узел (участник с пропуском)

Вы подключаете свой компьютер к сети.

### 1. Узнать свой ID

```sh
./rakkan-node id -key node.key
```

В первый раз команда создаст файл `node.key` — это **ключ вашего узла**.
Не теряйте его и никому не отдавайте. Команда напечатает ID узла
(`12D3KooW...`): отправьте его админу.

### 2. Получить пропуск

Админ пришлёт файл, например `vasya.cert`. Положите его рядом с `node.key`.

### 3. Запустить узел

Вам понадобятся:
- **ID сети** — его даст админ;
- **адрес любого работающего узла** — его тоже даст админ или любой
  участник. Узел печатает свой адрес при запуске, в строке `listening on ...`.

```sh
./rakkan-node daemon \
    -network <ID сети> \
    -key node.key -cert vasya.cert \
    -bootstrap /ip4/203.0.113.5/udp/4001/quic-v1/p2p/12D3KooW...
```

Если узлы стоят в одной домашней сети, `-bootstrap` можно не указывать:
они найдут друг друга сами.

Узел работает, пока его не остановите (Ctrl+C). Раз в 30 секунд он печатает
таблицу участников: кто подключён и с какой задержкой. После первого запуска
узел запоминает адреса соседей в `peers.json` и в следующий раз найдёт их
даже без `-bootstrap`.

### Полезные флаги

| Флаг | Что делает |
|---|---|
| `-workers 4` | сколько чужих задач считать одновременно; `0` — только отправлять свои |
| `-llm` | давать сети свой компьютер для кусков нейросетей |
| `-llm-mem-gb 8` | сколько памяти отдать под нейросети (по умолчанию 4 ГБ); с видеокартой — только под «память разговора» |
| `-gpu auto` | считать нейросети на видеокарте (по умолчанию выбирается лучшая сама). `-gpu off` — только процессор, `-gpu list` — показать видеокарты |
| `-gpu-mem-gb 6` | сколько видеопамяти отдать под нейросети (по умолчанию 85%) |
| `-store-gb 20` | сколько места на диске отдать под данные (по умолчанию 10 ГБ) |
| `-relay` | помогать соседям, которые сидят за роутером. Включайте, если у вашего компьютера «белый» IP |
| `-listen /ip4/0.0.0.0/udp/4001/quic-v1` | слушать фиксированный порт, чтобы адрес узла не менялся |
| `-isolation process` | более простая песочница, если строгая не запускается (не Linux, старое ядро) |
| `-free-credit 100` | сколько работы давать гостям в долг (в миллиардах единиц газа) |
| `-v` | подробный журнал, когда что-то идёт не так |

### 4. Отправлять задачи из своей программы

Узел открывает файл-сокет `rakkan.sock`, через который с ним общаются
программы на Node.js. Подключите SDK из папки `sdk/js`:

```sh
npm install /путь/к/rakkan-mesh/sdk/js
```

```js
import { connect } from '@rakkan/sdk';
import { readFileSync } from 'node:fs';

const mesh = connect({ socket: '/путь/к/rakkan.sock' });

// Посмотреть, кто в сети.
console.log(await mesh.status());

// Отправить задачу: программа в формате WebAssembly плюс входные данные.
const res = await mesh.run({ module: readFileSync('task.wasm'), input: 'привет' });
console.log(res.output.toString(), 'посчитал узел', res.node);
```

Готовые примеры лежат в `sdk/js/examples`: поиск хеша, миниатюры фото,
подсчёт слов, нейросети. Задачи можно писать на AssemblyScript (это почти
TypeScript), см. `sdk/as`.

### 5. Поговорить с нейросетью

Скачайте модель с [Hugging Face](https://huggingface.co), например
`Qwen/Qwen2.5-0.5B-Instruct`, в папку целиком. Нужны файлы `config.json`,
`tokenizer.json`, `tokenizer_config.json`, `generation_config.json` и
`*.safetensors`. Запустите несколько узлов с флагом `-llm` и выполните:

```sh
cd sdk/js
node examples/chat.js /путь/к/Qwen2.5-0.5B-Instruct "Почему небо голубое?"
```

Модель сама разрежется на куски по узлам. Чтобы она занимала меньше памяти,
в коде можно сжать её при загрузке:
`mesh.importModel({ hf: dir, quant: 'q8_0' })` — вдвое меньше почти без
потерь, `'q4_m'` — втрое меньше.

### Видеокарта

Если на компьютере есть видеокарта с поддержкой Vulkan (почти любая
современная: NVIDIA, AMD, Intel, на Mac через MoltenVK), узел найдёт её сам и
будет считать на ней куски нейросетей. Посмотреть, что он видит:

```sh
./rakkan-node daemon -gpu list
```

Звёздочкой отмечена видеокарта, которую узел возьмёт. Ничего настраивать не
нужно: ответы на видеокарте получаются точно такими же, как на процессоре,
поэтому такие узлы спокойно работают вперемешку. Сеть сама даёт мощным узлам
больше слоёв модели, а слабым меньше или ничего.

### Проверить задачу без сети

```sh
./rakkan-node run -input data.bin task.wasm
```

Задача выполнится в песочнице прямо у вас, без сети. Удобно для отладки.

## Гость (без пропуска)

Вы приходите в сеть, которую админ открыл для гостей. Пропуск не нужен.

### 1. Создать ключ

```sh
./rakkan-node id -key node.key
```

### 2. Запустить узел без пропуска

Нужны только ID сети и адрес любого узла:

```sh
./rakkan-node daemon \
    -network <ID сети> \
    -key node.key \
    -bootstrap /ip4/203.0.113.5/udp/4001/quic-v1/p2p/12D3KooW...
```

Если пропуска нет (файла `node.cert` рядом не окажется), узел сам поймёт,
что он гость. Дальше он:
1. спросит у соседа правила входа;
2. решит задачку у входа (напечатает `proving 24 bits of work...` и через
   несколько секунд `proof of work found`);
3. сохранит решение в `node.proof`, чтобы в следующий раз не решать заново;
4. войдёт в сеть.

Если сеть закрыта, узел так и скажет: `the network is closed`.

### 3. Что гостю можно

- **Отправлять задачи** — так же, как участнику (см. пункт 4 у узла).
- **Считать задачи для других** — и этим зарабатывать.

### 4. Кредит и репутация: как не стать изгоем

- **Кредит.** Каждый узел даёт гостю немного работы в долг. Израсходовали
  долг — задачи начнут отклонять с ошибкой `not enough credit`. Чтобы
  получить ещё, оставьте свой узел работать с `-workers` больше нуля: считая
  для других, вы гасите долг.
- **Репутация.** Ваши ответы сначала проверяют все, потом всё реже. Чем
  дольше вы работаете честно, тем больше вам доверяют и тем больше дают в
  долг.
- **Обман не окупается.** Если ваш ответ разойдётся с проверкой, узел,
  который это заметил, выгонит вас на сутки, а репутация сгорит. Новый
  ключ — это новая задачка у входа и репутация с нуля.

Посмотреть, как к вам относится сеть, можно так:

```js
const st = await mesh.status();
console.log(st.guest ? 'я гость' : 'я участник', 'сеть открыта:', st.open);
for (const p of await mesh.trust()) {
  console.log(p.id, 'репутация', p.score, 'долг', p.served - p.consumed);
}
```

### 5. Как стать участником

Попросите админа выдать пропуск на ваш ID (команда `rakkan-node id`
напечатает его снова). Положите пропуск рядом с ключом и перезапустите узел
с `-cert ваш.cert`: теперь вы полноправный участник, без долгов и проверок.

## Если что-то не работает

| Что видно | Что делать |
|---|---|
| `members: 0 connected` | Проверьте `-bootstrap`: адрес должен заканчиваться на `/p2p/<ID узла>`. Проверьте, что ID сети тот же |
| `certificate is for ..., but the key is ...` | Пропуск выдан на другой ключ. Отправьте админу вывод `rakkan-node id -key node.key` |
| `certificate not currently valid` | Срок пропуска истёк или часы компьютера сбиты. Попросите новый пропуск или поправьте время |
| `certificate revoked` | Вас внесли в чёрный список. Разговор с админом |
| `the network is closed` | Гостей сейчас не пускают. Нужен пропуск |
| `not enough credit` | Вы гость и исчерпали долг. Посчитайте что-нибудь для сети |
| `process isolation is only supported on Linux` | Вы не на Linux. Добавьте `-isolation process` |
| Узел падает при запуске с ошибкой про namespaces, seccomp или `operation not permitted` | Система не разрешает строгую песочницу (часто в контейнерах). Попробуйте `-isolation ns`, а если не поможет — `-isolation process` |
| `no member can run this task` | Нет свободных узлов с нужными возможностями, или задача просит больше памяти и газа, чем разрешают узлы |
| Что-то непонятное | Запустите узел с `-v` и посмотрите журнал |
